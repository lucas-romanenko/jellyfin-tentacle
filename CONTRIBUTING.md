# Contributing

Thanks for helping. The maintainer's agent picks up every new issue and
pull request: bugs are fixed, deployed and answered on the issue; features
wait for the maintainer's decision. Replies starting "Automated (Dev):"
come from that agent.

## Bugs

- One issue per bug, written so it can be reproduced: what you did, what
  happened, what you expected, plus versions (Tentacle server commit from
  `/api/version`, plugin version, Jellyfin version, the client and its
  version).
- Search open and closed issues first. A follow-up to an earlier fix links
  it ("follow-up to #627") instead of repeating the whole story.
- An issue is enough; a pull request isn't needed. If you send a fix,
  write "(#N)" in it, not "Fixes #N", so the issue stays open until the fix
  is deployed and answered.

## Test-only pull requests

Bundle them: at most one pull request per area per week (for example
"Tests: Live TV guards, week of Oct 19"), not one per pinned test.

## Features and ideas

- Open a feature request issue first, saying who it helps and why. Please
  don't send a pull request for a feature until it's approved on the issue.
- Product direction: Home shows only the library, what you have and can
  watch right away. Discover is its own page, so no Discover rows on Home.
